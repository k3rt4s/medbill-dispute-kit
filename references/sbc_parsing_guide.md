# Summary of Benefits and Coverage parsing guide

`scripts/parse_sbc.py` reads an ACA Summary of Benefits and Coverage (SBC) text layer and writes `<HEALTHBILLS_ROOT>/_sbc_profiles/<plan_slug>.json`. Each field is an envelope: `{ "value": ..., "source": "text"|"model"|null, "page": <zero-based page>|null }`. The deterministic pass uses the SBC's question boundaries and network labels first. It leaves ambiguous or absent values null.

The SBC format and its required content come from [45 CFR 147.200](https://www.ecfr.gov/current/title-45/subtitle-A/subchapter-B/part-147/subpart-B/section-147.200) and the Department of Labor's [SBC information page](https://www.dol.gov/agencies/ebsa/laws-and-regulations/laws/affordable-care-act/for-employers-and-advisers/summary-of-benefits). Sources reviewed 2026-09-07.

## Profile fields

| Fields                                                                                                                                                                                                                                                                                                                        | Text region                                                                                 | Use                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `plan_name`, `plan_year_start`, `plan_year_end`, `coverage_period`                                                                                                                                                                                                                                                            | Corresponding labeled line                                                                  | Identifies the supplied SBC and its stated coverage period.              |
| `in_network_deductible_individual`, `in_network_deductible_family`, `out_network_deductible_individual`, `out_network_deductible_family`                                                                                                                                                                                      | Overall-deductible question, bounded before the next SBC question and other network column  | Requires one explicit individual and family amount per network column.   |
| `in_network_oop_max_individual`, `in_network_oop_max_family`, `out_network_oop_max_individual`, `out_network_oop_max_family`                                                                                                                                                                                                  | Out-of-pocket-limit question, bounded before the next SBC question and other network column | Requires one explicit individual and family amount per network column.   |
| `out_of_pocket_exclusions`, `overall_annual_plan_limit`, `referral_needed_for_specialist`                                                                                                                                                                                                                                     | Corresponding question or labeled line                                                      | Preserves the stated response without changing it to a legal conclusion. |
| `network_provider_check_url`, `plan_phone_number`                                                                                                                                                                                                                                                                             | Corresponding contact line                                                                  | Preserves the stated directory and phone route.                          |
| `primary_care_visit_cost_sharing`, `specialist_visit_cost_sharing`, `diagnostic_test_cost_sharing`, `imaging_cost_sharing`, `emergency_room_cost_sharing`, `emergency_medical_transportation_cost_sharing`, `urgent_care_cost_sharing`, `hospital_stay_facility_fee_cost_sharing`, `hospital_stay_physician_fee_cost_sharing` | Common-service table row or its next text line                                              | Stops before the next recognized service row or question.                |
| `erisa_subject`, `grievance_appeal_contact`                                                                                                                                                                                                                                                                                   | Optional labeled line                                                                       | Records an explicit disclosure or contact only when supplied.            |

## Fallback and review

For fields still null after deterministic extraction, the non-dry-run path can build a bounded model request. It imports OpenAI and reads the configured credential file only inside that fallback function. The fallback accepts only requested supported scalar fields, records them as `source: "model"`, and cannot overwrite a text-derived value. Unknown keys or object-shaped purported evidence are rejected. `--dry-run` performs PDF extraction and prints the complete request preview without importing a client, reading an environment file, writing a profile, or making a network call.

The parser does not calculate amounts, decide ERISA coverage, or infer missing values. Check every output fact against the SBC before relying on it in an appeal or IDR request.
